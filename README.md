# ACadSmartLeader

Умные мультивыноски AutoCAD на C#. Плагин читает `BobrovXDATA` цели и вычисляет верхнюю и нижнюю полки настоящим Core [acadPaletteSetXDATA](https://github.com/veb86/acadPaletteSetXDATA), закреплённым на **v0.0.143**. Например: двигатель — «М1» / «7,50 кВт», кабель — «ЩУ1.3» / «ВВГнг-LS 5x2,5» в культуре ru-RU.

Реализованы этапы 1–4 [ТЗ](docs/TZ-smart-leader.md). **Приёмка в AutoCAD пока не выполнена**: в среде разработки нет лицензированного AutoCAD. Сборка и тесты Core не подтверждают геометрию полок, Undo, совместную загрузку и время обновления в CAD. Точный список незавершённых проверок и воспроизводимые сценарии — в [протоколе приёмки](docs/acceptance.md). Подлинный `examples/demo.dwg` ещё нужно получить командой `SL_DEMO` на этом хосте.

## Установка

Артефакт workflow **Build and test** содержит `ACadSmartLeader-0.1.0.zip`. Распакуйте папку `ACadSmartLeader.bundle` в `%APPDATA%\Autodesk\ApplicationPlugins`, затем перезапустите AutoCAD. При необходимости добавьте путь в доверенные расположения AutoCAD. Пакет содержит отдельные сборки для AutoCAD 2021–2024 (.NET Framework 4.8) и 2025+ (.NET 8), меню CUIX, исходные правила и демонстрационную схему.

Альтернатива для разработки — `NETLOAD` соответствующей `ACadSmartLeader.dll`; JSON и CUIX должны лежать рядом. Зависимости NCalc 7.4.0 встроены в DLL, библиотеки AutoCAD поставляются самим AutoCAD. Палитра не обязательна для запуска выносок, но нужна для удобного редактирования данных цели.

## Работа

1. У цели должны быть данные `BobrovXDATA` v2. Схема `VELEC` даёт подписи справочников, точность, формулы и значения по умолчанию.
2. `SL_CREATE`: укажите точку стрелки с привязкой «Ближайшая», затем место полки с предпросмотром. Если под стрелкой нет цели, выберите её вручную. Ключ `_Rule` задаёт правило явно.
3. Измените данные цели в палитре, затем выполните `SL_UPDATE`. По умолчанию обновление также ставится отдельной командой после `REGENALL`.
4. `SL_RULES` редактирует правила текущего чертежа: порядок, фильтры, форматы, стиль, слой, предпросмотр и вставка `@@[Id]`. Правила сохраняются в NOD `VELEC_LEADER`, исходный JSON копируется при первом создании.

| Команда | Назначение |
| --- | --- |
| `SL_CREATE` | Создать одну нативную MLeader с одной стрелкой |
| `SL_UPDATE` | PickFirst либо `_All` / `_Select`; `_Force` разрешает замену ручного текста, затем выбирается область обновления |
| `SL_EDIT` | Правило и собственные форматы одной выноски, предпросмотр, перепривязка |
| `SL_RULES` | Правила чертежа |
| `SL_RULES_IMPORT`, `SL_RULES_EXPORT` | Проверка и перенос JSON, включая неизвестные поля |
| `SL_SELECT_PROBLEMS` | Выбрать отвязанные, ошибочные и вручную изменённые выноски текущего пространства |
| `SL_SETTINGS` | Off / Regen / RegenAll и допуск привязки; настройки в `%APPDATA%\ACadSmartLeader\settings.json` |

Форматы совпадают с палитрой: `@@[Power] кВт`, `@@[Voltage:key]`, `=@@[Power] & ' кВт'`, `IF`, `ROUND`, `@@@@`. Ошибки синтаксиса/ссылок показываются предупреждением при импорте и в диалоге, правило можно сохранить для будущей схемы. При вычислении ошибочная полка получает `#ОШИБКА` или заданный `error`. Полка со всеми пустыми подстановками получает `empty`.

Обновление сохраняет ручной текст без `_Force`, пропускает заблокированные слои и xref, пишет только изменения одной транзакцией. Отвязка сохраняет текст и исходный handle для восстановления после Undo удаления. При поиске по `DEVICE_ID` дубликат считается неоднозначным. Цель и выноска должны быть в одном пространстве; внутри блока выбирается вставка верхнего уровня. Выноска без плагина остаётся обычной MLeader с последним текстом.

Свои `TOP`/`BOTTOM` ограничены 255 байтами UTF-8 XDATA; длинный формат храните в правиле. Пустая собственная полка отключает её, отсутствие переопределения наследует правило. При ручном обновлении отчёт перечисляет ошибки, перепривязки и итоговые счётчики. Для дополнительной диагностики задайте `SMARTLEADER_TRACE=1` перед запуском AutoCAD; по умолчанию трассировка выключена.

Свойства `@@[$…]`, несколько стрелок, блоки с атрибутами и мгновенное обновление по изменению цели относятся к этапу 5, принятому ТЗ «по отдельным задачам».

## Сборка и проверки

Требуются Git, .NET SDK 8 и для меню/рендера/пакета — Windows. Лицензия AutoCAD нужна для приёмки, для компиляции используются NuGet reference assemblies.

```sh
git submodule update --init
dotnet test tests/ACadSmartLeader.Core.Tests -c Release --blame-hang-timeout 2m
dotnet build src/ACadSmartLeader -c Release -m:1
```

На Windows из корня репозитория:

```powershell
dotnet run --project experiments/MenuBuilder -c Release -- artifacts/ACadSmartLeader.cuix
dotnet run --project experiments/WpfRender -c Release -- artifacts/screenshots
./build/package.ps1
```

CI выполняет тесты Core, обе сборки плагина, создание меню, рендер настоящих WPF-диалогов и упаковку. [План и матрица требований](docs/implementation-plan.md) связывают требования с проверками. При разработке на Linux с одним runtime .NET 10 тесты можно запускать с `DOTNET_ROLL_FORWARD=Major`; CI использует .NET 8.

## Демонстрация и эксперименты

- `SL_DEMO` в новом пустом чертеже создаёт схему, двигатель и кабель с данными и выносками. Сохраните как `examples/demo.dwg` после визуальной проверки. Команда отказывается менять уже заполненный чертёж.
- `SL_DEMO_POWER`, `SL_DEMO_ASSERT`, `SL_DEMO_PERF` и [скрипт](experiments/AutoCadAcceptance/create-update-undo.scr) помогают воспроизвести приёмку, включая ограниченный пример на 1000 выносок.
- [`experiments/WpfRender`](experiments/WpfRender/Program.cs) рендерит те же классы диалогов без AutoCAD. Снимки не заменяют проверку в AutoCAD.
- [`experiments/LabelFormatCheck`](experiments/LabelFormatCheck/Program.cs) — исходный эксперимент вычисления полок настоящим Core. [Результат](experiments/LabelFormatCheck/output.txt).
- [`experiments/AcadApiProbe`](experiments/AcadApiProbe/Program.cs) читает метаданные AutoCAD без выполнения его кода; им проверены факты приложения А ТЗ.
